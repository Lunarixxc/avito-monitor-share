# Переход на parser_avito: подготовка и реальная проверка

2026-09-19. Владелец разрешил полностью менять реализацию ради стабильного сбора.
Целевой вариант — полное ядро parser_avito, а не сохранение старого collector.
Глобальная сеть не менялась: отдельный HTTP proxy достаточен для нового транспорта.

## Что проверено

- Из временной offline-копии нашего Chromium-профиля извлечены 10 cookies.
  Исходный профиль не открывался и не изменялся. Экспорт закрыт правами 600.
- Оригинальные OwnCookiesProvider и HttpClient отправили один запрос к
  `/web/1/js/items` через прямой транспорт eno1/0x2024.
- В 19:06:11 MSK получен **HTTP 403, application/json**, ключ ответа
  `too-many-requests`, присутствует указание CAPTCHA. Свежих объявлений нет.
  Автоповторов не было; временный транспорт остановлен.
- Доказательства: `evidence/2026-09-19T16-06-11.708067+00-00/summary.json`;
  сырой ответ сохранён отдельно с ограниченным доступом.
- SPFA converter повторно вернул `/web/1/js/items`. Это расходится с примером
  `m.avito.ru/api/11/items` в его документации; перед длительным платным запуском
  совместимость выданных cookies/fingerprint и реального endpoint требует проверки.

Существующие cookies не решили блокировку. Следующий кандидат — авторизованный
внешний HTTP-прокси + SPFA cookies/fingerprint. Работоспособность этого варианта
пока не подтверждена. [Документация сервиса](https://spfa.pro/api/docs/)
требует персональный ключ и proxy `login:password@host:port`.
Публичные прокси этот метод не принимает.

## Подготовленный запуск

`run_upstream.py` использует настоящий `AvitoParse`: его модели, фильтры,
SQLite, converter, HTTP client, SPFA provider и Excel exporter. GUI не нужен.
Checkout upstream не изменён. Изменения ограничены исследовательской обвязкой.

- `.env`: SPFA_API_KEY, AVITO_PROXY, AVITO_SEARCH_URL; секреты не печатаются.
- Без аргументов — только офлайн-проверка конфигурации, никаких сетевых запросов.
- `--once` — одна страница, одна попытка HTTP; цикл мониторинга ещё не включён.
- Новая покупка cookies запрещена без `--allow-cookie-purchase`.
- С этим флагом разрешена максимум одна попытка покупки за запуск. Суммарный
  месячный бюджет wrapper не контролирует; регулярный запуск пока не настроен.
- Рабочие файлы: `runtime/storage/`, `runtime/database.db`, `runtime/result/`,
  `runtime/last_run.json`. Каталог закрыт правами 700; файлы создаются при umask 077.
- Telegram/VK и получение телефонов отключены. Секретные логи upstream отключены.
- Успешный HTTP-запрос не равен успешной выдаче: нужно отдельно сверить экспорт,
  географию, цену, ID и повторяемость. Старый Excel не считать свежим результатом.

Проверены полный импорт приложения и синтетический цикл с пустым каталогом без
сети; четыре теста: offline config, ошибочный URL, запрет покупки по умолчанию,
отсутствие повторной покупки после ошибки. py_compile и pip check прошли.
У upstream обнаружено предупреждение о незакрытом SQLite connection при завершении
процесса; это нужно исправить до постоянной службы, если источник заработает.

## Что требуется от владельца

Определить допустимый бюджет, получить ключ SPFA и выделенный авторизованный
HTTP-прокси, затем заполнить **локальный** `.env`. Реквизиты не отправлять в чат.
В текущем окружении эти значения отсутствуют. Покупки/регистрации не выполнялись.
По [тарифам SPFA](https://spfa.pro/tariffs/) на дату проверки отображаются cookies
за 3 ₽ и бонус 50 ₽ после подтверждения почты. Это не гарантия срока работы или
стоимости месяца; прокси оплачивается отдельно, фактическую цену проверять до покупки.

```bash
cd /home/asat/codex-work/avito-monitor/research/parser-avito
nano .env
.venv/bin/python run_upstream.py
.venv/bin/python -m unittest test_run_upstream -v
```

После заполнения настроек и разрешения трат первый реальный запуск:

```bash
.venv/bin/python run_upstream.py --once --allow-cookie-purchase
```

Команда может списать стоимость одного набора cookies. Следующие диагностические
запуски с существующими cookies — `--once` без флага покупки. При блокировке новый
запуск не назначать вслепую; проверить причину, срок сессии и согласованность IP.

Критерий завершения: реальная выдача с нужной географией, повторные успешные циклы,
проверка пагинации, затем наблюдение 24 часа с интервалом 30–60 минут. Пока этот
критерий не выполнен, проект не объявляется стабильно работающим.
