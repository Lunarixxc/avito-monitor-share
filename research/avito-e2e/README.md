# Avito-Parser: успешная проверка 2026-09-20

## Поиск по категории вместо ключевых слов — 2026-09-29

Плановый сбор теперь запрашивает категорию «Ноутбуки» в Казани без `q/query`;
чередование «игровой ноутбук», RTX, Legion, Nitro и TUF отключено. Сортировка
по-прежнему запрашивается через `s=104`; абсолютный порядок публикаций не доказан.
Диапазон 35 000–65 000 ₽ включительно проверяется локально, после получения выдачи. Ручной
`run_once.py` допускает явный `AVITO_SEARCH_QUERY`, по умолчанию запрос пустой.

Обычный цикл читает страницы 1/2/3 и одну страницу последовательного обхода:
сначала 4, затем 5, 6 и далее. Курсор сохраняется в `state.json: catalog_scan`
только после успешного импорта. Пустая или повторившаяся глубокая страница
возвращает обход к 4. Контроль после блокировки по-прежнему читает одну страницу
и до трёх карточек, сохраняя курсор. Лимит обычного цикла — четыре страницы,
12 карточек, 32 HTTP-запроса и 150 секунд; расписание 09/11/13/15/17/19/21 МСК.

Название без модели GPU больше не исключает объявление из очереди чтения:
до двух свободных мест выделяются неизвестным комплектациям. Подсказки GPU
берутся также из описания выдачи; заголовки MacBook/макбук без подходящей GPU
не занимают места первичной разведки. Непрочитанные объявления остаются
в очереди до 30 дней, даже выпав из выдачи. Прочитанные неподходящие карточки
при той же цене повторно не занимают эту очередь. Обычная перепроверка известных
кандидатов и приоритет вечернего топа сохраняются. Неизвестная GPU не становится
подходящей автоматически: отправка требует поддерживаемой GPU, цены и наличия,
подтверждённых карточкой.

`latest.json: search_coverage` и `latest.md` показывают фактические страницы,
следующую глубокую страницу и очередь первичного чтения. Отсутствие пересечения
трёх первых страниц с предыдущим циклом обозначается как возможный пропуск.
Пересечение и завершение глубокого обхода не доказывают полноту рынка:
выдача меняется, а очередь может расти быстрее лимита карточек.
HTTP 400/404 только на глубокой странице, при трёх успешно прочитанных первых,
фиксируется как незавершённый глубокий обход и возвращает курсор к 4, сохраняя
свежую выдачу. Ошибки первых страниц и защитные 403/429 не маскируются.

Изменения вступают в силу со следующего запуска oneshot-службы; перезапуск
не нужен. На момент изменения таймер активен, следующий запуск — 30.09 в 09:00 МСК.
Живой сбор и Telegram-отправка при внедрении не выполнялись.
Проверены 105 существующих проектных и 33 upstream-теста, `py_compile`
для `monitor.py run_once.py filters.py tracking.py lifecycle.py`,
`git diff --check` и локальные предпросмотры без сети.

## Скрытие объявлений в Telegram — 2026-09-27

Под частями вечернего топа есть кнопки «🙈 Убрать №…». Команда
`/hide <ссылка Авито или ID>` делает то же; `/show <ссылка или ID>` возвращает
объявление. `/start` показывает подсказку, `/cancel` завершает ввод (активного
диалога нет). Команды и кнопки принимаются только из личного чата владельца,
указанного в `TELEGRAM_CHAT_ID`. Отдельная служба
`avito-telegram-control.service` обрабатывает их через aiogram 3 polling.

Скрытие хранится в `results/monitor/state.json`. Объявление исключается из
следующих топов, блока «Похожие б/у», спорных позиций и обычных дневных событий;
место в топе занимает следующий вариант. Уже доставленные сообщения не удаляются.
Незавершённые части дайджеста при повторной отправке исключают скрытые позиции.
После любого изменения цены, **подтверждённого чтением карточки**, скрытие
снимается; одной цены из выдачи недостаточно. Скрытые объявления продолжают
проверяться обычной очередью карточек. Старая кнопка с прежней ценой отклоняется.

Перед включением службы сохранена копия
`results/monitor/state-before-telegram-control-20260927.json`. Проверка без
отправки сообщений: `.venv/bin/python -m pytest -q test_*.py`,
`.venv/bin/python notifications.py`, `systemctl is-active avito-telegram-control.service`.

## Обработчик защиты карточек — 2026-09-22

`run_once.fetch_card` теперь использует обработчики закреплённой версии
[Avito-Parser](https://github.com/mickberrad659-sketch/Avito-Parser/blob/2d09315ead7ef1b3498415474f690eea512cf571/main.py):
QRATOR через `run_qrator_cookie_flow`, PoW/GeeTest/dispatcher через
`handle_firewall_response`. После успешной проверки повторяется тот же URL
в той же сессии, перед GET восстанавливаются document-заголовки. Upstream не менялся.

Лимит карточки: три перехода защиты, максимум один QRATOR и один GeeTest/dispatcher.
Общие 32 HTTP/150 секунд действуют также на вложенные запросы. Ошибка обработчика,
неподдерживаемая защита или исчерпание лимита останавливают карточки и включают
выдержку; уже прочитанные данные сохраняются. Обычные 404/410 обрабатываются как
раньше. HTTP 200 с блокировкой не считается карточкой объявления.

В `cards[].protection` сохраняются только HTTP-статусы, типы защиты, число переходов,
причина остановки и класс ошибки. HTML защиты, заголовки, cookies, challenge и
тексты исключений не сохраняются. Сохранение upstream HTTP-дампов выключено;
stdout/stderr вложенных обработчиков подавлены. Неподдерживаемые solver-задачи
не становятся автоматическими бесконечными повторами.

Проверка: 94 offline-теста и py_compile. Живой результат
`results/protection-check-20260922/summary.json`: 50 объявлений, четыре HTTP 200,
из них Acer 8425023534 явно снят, три другие карточки active. Защита карточек
не появилась: её преодоление вживую пока не подтверждено. Выдача прошла PoW.
Два вызова DeepSeek без ошибок, обогащённый результат импортирован; рабочая пауза
архивирована после успешной проверки. Backup кода: `results/card-protection-backup-20260922/`.

## Восстановление и полная подборка — 2026-09-22

Этот раздел заменяет прежние правила бессрочной паузы и исключительно свежего топа.

- После ошибки сохраняется `paused.json` с причиной, `attempts`, `retry_after`.
  Выдержка 2/4/8/16/24 часа, далее 24; попытка только в ближайший разрешённый
  слот 09/11/13/15/17/19/21 МСК после этого времени. Для плановых запусков
  выдержка отсчитывается от начала слота, чтобы несколько секунд задержки
  systemd не пропускали следующий двухчасовой слот. Внутри паузы HTTP к Авито нет.
  Контрольная попытка ограничена одной страницей и тремя карточками.
  При успешной проверке пауза переносится в `pause-history.jsonl`; нормальный
  объём возвращается со следующего слота. Старые `paused.json` без retry_after
  интерпретируются как двухчасовая выдержка от `at`.
- О сбое и восстановлении отправляются Telegram-уведомления. Очередь и
  квитанции: `collection_health.json`; ошибки отправки повторяются в следующие
  слоты мониторинга/дайджеста. Сетевой timeout после приёма сообщения Telegram
  всё ещё может дать дубль. Частичный сбор отмечен отдельно от полного.
- Циклы 17:00 и 19:00 обновляют до десяти лучших известных кандидатов прежде
  новых объявлений; сначала карточки старше двух часов, затем по рейтингу.
  `run_once.py --prepare-digest` включает тот же приоритет при ручной проверке.
  Между карточками по умолчанию четыре секунды. Это не гарантирует отсутствие 429.
- Подборка содержит до десяти вариантов: сначала свежие (не старше трёх часов),
  затем ранее подходившие с проверкой не старше 72 часов. У последних явно
  отмечены необходимость перепроверки, дата и последняя цена именно карточки.
  Снятые/проданные/недоступные и карточки с последующим 404 не добавляются.
  Непрочитанные карточки и неподходящие GPU не используются для заполнения числа.
- До трёх спорных конфигураций вынесены отдельно и не считаются подтверждённым
  топом. Ассортимент не допускается. Не гарантируются пять свежих вариантов при
  ограничении источника или недостатке подходящих объявлений.
- Переменные окружения: `AVITO_RETRY_BASE_HOURS` (2), `AVITO_RETRY_MAX_HOURS`
  (24), `AVITO_CARD_DELAY_SECONDS` (4, допустимый диапазон 2–10 секунд).
  Расписание, бюджет 65к, требования RTX 3050+ и семантические лимиты прежние.

Интеграция через requests и официальный API, без нового SDK/зависимостей.
