# Avito Monitor

Мониторинг игровых ноутбуков на Авито: сбор выдачи и карточек, история
проверенных цен, фильтрация, дневные уведомления и вечерняя подборка в Telegram.

Это отдельная копия текущего кода от 23.10.2026. Личная wiki, история Git,
`.env`, cookies, браузерные профили и результаты сборов в неё не входят.
Приложение и расписание после клонирования автоматически не запускаются.

Рабочая реализация находится в `research/avito-e2e/`. Остальные каталоги
`research/` и их отчёты сохраняют предыдущие эксперименты. Старые README
описывают историю настройки на другом сервере; начинать следует с этого файла.

## Что настроено в коде

- Категория «Ноутбуки», Казань; бюджет 35 000–65 000 ₽.
- Поддерживаемые игровые RTX, включая RTX 2070; правила в `filters.py`.
- Цена и наличие подтверждаются чтением карточки; исчезновение из выдачи
  само по себе не считается продажей.
- Обычный цикл: четыре страницы, до 12 карточек, ограничение запросов и времени.
- После ошибок предусмотрена пауза с ограниченными контрольными попытками.
- Telegram: уведомления, вечерний топ, `/start`, `/hide`, `/show`, `/cancel`
  и кнопки скрытия. Дополнительное извлечение характеристик через DeepSeek
  включается отдельно.

Город, поддерживаемые GPU и часть ценовых правил заданы в Python-коде;
это ещё не универсальный сервис с настройками через интерфейс.

## Установка на Linux

Нужны Git и Python 3 с поддержкой `venv`. Исходная рабочая среда — Python 3.14.
Корневой `requirements.txt` относится к старым браузерным экспериментам;
для рабочего мониторинга используется отдельный файл ниже.

```bash
git clone https://github.com/Lunarixxc/avito-monitor-share.git
cd avito-monitor-share/research/avito-e2e
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
git clone https://github.com/mickberrad659-sketch/Avito-Parser.git upstream
git -C upstream checkout --detach 2d09315ead7ef1b3498415474f690eea512cf571
cp .env.example .env
chmod 600 .env
```

Парсер загружается отдельно в игнорируемый `upstream/` и закреплён на версии,
с которой работает обёртка. Не заменяй её последним коммитом без проверки.

## Проверка без сетевых запросов

Команды выполняются из `research/avito-e2e/`:

```bash
.venv/bin/python -m pytest -q test_*.py
AVITO_DIRECT_PROXY='' .venv/bin/python run_once.py
.venv/bin/python monitor.py
```

Без `--live` сборщик показывает конфигурацию. `monitor.py` без аргументов
тоже показывает конфигурацию и создаёт локальный каталог состояния.

## Первый сбор вручную

```bash
AVITO_DIRECT_PROXY='' .venv/bin/python run_once.py --live --pages 1 --details 3 --run-id first-check
```

Это реальный запрос к Авито, без отправки Telegram. Результат появится в
`results/first-check/summary.json`. Один `run-id` разрешён только для одной
попытки; для следующей выбери новое имя. Доступность Авито зависит от сети
и защиты сайта; успешный сбор на другом сервере не гарантируется.

Пустой `AVITO_DIRECT_PROXY` выбирает прямое соединение. Для своего прокси
передай его адрес через эту переменную окружения. Настройки `AVITO_*`
читаются из окружения оболочки или systemd, а не из `.env`.

## Telegram и дополнительный анализ

В `research/avito-e2e/.env` заполни собственные `BOT_TOKEN` и
`TELEGRAM_CHAT_ID`; включи отправку через `TELEGRAM_ENABLED=1`.
Укажи доступный `TELEGRAM_PROXY`: отдельный обработчик команд
`telegram_control.py` требует прокси. Адрес `127.0.0.1:18080` из шаблона
работает только при наличии локального прокси на этом порту.
Не используй токен или чат прежнего владельца.

DeepSeek необязателен: оставь `DEEPSEEK_ENABLED=0`, если он не нужен.
Ключи хранятся только в локальном `.env`, который исключён из Git.

## Расписание

В `research/avito-e2e/systemd/` сохранены примеры служб и таймеров:
сбор в 09/11/13/15/17/19/21 МСК, вечерняя подборка в 20:00.
Перед установкой замени пользователя и абсолютные пути в unit-файлах,
а также настрой транспорт. Примеры ссылаются на исходный сервер.
`diagnostic_proxy.py` использует его сетевой интерфейс и правила маршрутизации;
для другой машины требуется адаптация. `AVITO_DIRECT_PROXY` в службе
должен соответствовать выбранному транспорту.

Для проверки проекта устанавливать systemd-службы не требуется.
История, состояние пауз и квитанции отправки создаются локально в `results/`.
